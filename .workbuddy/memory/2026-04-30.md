## Jekyll 本地环境依赖冲突解决

**问题背景**：nswm-lab.github.io (academicpages 模板) 在 Windows + Ruby 3.1.6 + Bundler 2.4.22 下无法启动本地测试。

**根因链**：
1. `jemoji` 在 `_config.yml` plugins 中但 Gemfile 已注释 → 移除 _config.yml 中的 jemoji
2. `http_parser.rb` (em-websocket 依赖) 的 C 源码与 Ruby 3.1 `ANYARGS` API 不兼容 → bundle config 绕过 + 通过 `em-websocket ~> 0.5.2` 锁版
3. `sassc` (jekyll-sass-converter 2.x 依赖) 的 libsass.so 在 Windows 路径加载失败 → 改用 jekyll-sass-converter 3.x + sass-embedded
4. `bigdecimal 4.x` (google-protobuf 4.31+ 依赖) 需要编译 → 锁死 `sass-embedded ~> 1.86.0` + `google-protobuf ~> 4.30.2` + `bigdecimal 3.1.1`
5. `_config.yml` plugins 中的 `jekyll-gist` 未在 Gemfile 声明 → 补充

**最终 Gemfile 关键锁定版本**：
- jekyll 4.3.2（精确版本）
- jekyll-sass-converter ~> 3.0
- sass-embedded ~> 1.86.0 (x64-mingw-ucrt 预编译)
- google-protobuf ~> 4.30.2 (x64-mingw-ucrt 预编译)
- bigdecimal 3.1.1（Ruby 3.1 内置版本，阻止升级）
- jekyll-gist、jekyll-paginate（补充声明）

**结果**：`bundle exec jekyll serve` 在 http://127.0.0.1:4000 正常运行，HTTP 200。

**注意**：Sass DEPRECATION 警告不影响功能，是 _sass/ 下的旧 vendor 代码问题。

## 样式修复与服务器管理（22:09）

**问题**：用户多次反映网站无法访问、样式错乱。
**根本原因**：
1. PowerShell PATH 中 `C:\Program Files\` 导致所有 `execute_command` 报 Conda 模块解析错误
2. `bundle exec jekyll build` 输出有 WARNING 但 exit code 0，实际构建成功（done in 3.332s）
3. `_rebuild.bat` 的 `start /b python` 在 `cd _site` 后 `cd ..`，导致服务器 serving 根目录而非 `_site`

**正确操作流程**：
1. 重建：`cd "C:\Users\Eg4m1\Desktop\nswm-lab.github.io" && bundle exec jekyll build`
2. 启动服务器：`cmd /c "start /b python -m http.server 4000"` 在 `_site` 目录

**最终验证通过**（所有页面可访问）：
- http://localhost:4000/ ✅
- http://localhost:4000/cv/ ✅
- http://localhost:4000/publications/ ✅

**生成文件关键样式确认**（grep 验证 `_site/index.html`）：
- `#060e1e` 深色导航栏 × 6 处 ✅
- `width: 240px; height: 240px;` 照片尺寸 ✅
- Hero 渐变背景 `#060e1e → #0f2744 → #1a3a6b` ✅
- 无 `lab-global.css` 引用 ✅

**重要教训**：
- PowerShell 环境损坏（PATH 含 `C:\Program Files\`），所有命令改用 `cmd /c "..."` 执行
- `_rebuild.bat` 中 `cd _site` + `start /b` 顺序无效（`start` 启动独立进程），需要用 `_rebuild.bat` 只做 build，然后用单独的 serve.bat 启动 Python
- 每次改完源文件，必须 `bundle exec jekyll build` 重建，再重启服务器
- 上线前记得把 `_config.yml` 的 `url:` 改回 `https://nswm-lab.github.io/` 再重建推送

**涉及文件**：
